# AI Voice Input 需求文档

## 1. 产品定位

AI Voice Input 是一个 macOS 桌面端语音输入助手。它以系统托盘方式常驻后台，用户通过全局快捷键触发语音输入或语音问答。应用负责录音、语音转文字、调用大模型优化内容，并尽可能将最终文本自动填入用户当前正在使用的输入位置（输入框、编辑器、聊天框等）；若无法自动填入，则将结果保存到剪贴板作为兜底，确保内容不丢失。

产品核心目标：**让用户在任何输入场景中，用语音快速生成干净、可用、经过大模型优化的文字。**

## 2. 目标用户

主要面向需要频繁输入大量文字的人群，包括但不限于：

- 写作者、编辑、内容创作者
- 日常聊天、社交沟通用户
- 办公人员（邮件、文档、报告）
- 程序员（注释、文档、代码描述）
- 客服、运营人员
- 知识工作者、研究者

用户的核心诉求：

- 减少键盘输入负担，提升文字产出效率
- 不需要在每次使用前进行复杂配置
- 应用应尽量后台化、低打扰、即用即走
- 状态反馈清晰，出现权限或异常时能明确引导

## 3. 核心使用场景

### 3.1 语音输入

用户在任意应用中聚焦输入框，按住语音输入快捷键开始录音，松开后结束录音。应用自动完成以下流程：

1. 将语音转为文字
2. 根据润色提示词对文本进行纠错、去重复、断句优化
3. 将最终文本优先填入当前输入框
4. 若填入失败，则将文本写入剪贴板并提示用户

### 3.2 语音问答

用户按住语音问答快捷键开始提问，松开后应用自动完成以下流程：

1. 将语音转为文字（作为问题）
2. 调用大模型进行回答（使用问答提示词）
3. 通过轻量方式（通知、弹窗或专用查看窗口）提醒用户查看答案
4. 用户可点击查看完整回答，并可复制答案

语音问答和语音输入是两套独立的快捷键，互不混淆。

### 3.3 后台常驻

用户关闭主设置窗口后，应用仍继续在后台运行，快捷键持续可用。用户可通过系统托盘入口：

- 重新打开主窗口进行设置
- 查看应用状态
- 退出应用

## 4. 核心功能需求

---

### 4.1 语音录制

#### 4.1.1 录音触发方式

- 用户按下快捷键（可配置）开始录音
- 用户松开快捷键停止录音
- 同一时间只能存在一个录音任务（语音输入和语音问答互斥）

#### 4.1.2 录音状态反馈

录音全过程的状态必须明确可见，包括：

- **录音开始**：显示动画状态浮窗，提示用户“正在录音”
- **录音进行中**：浮窗持续显示，带有脉动/呼吸动画效果，给用户明确的视觉反馈
- **录音结束**：浮窗状态切换为“正在转写”
- **录音异常**：若录音失败（如麦克风不可用），浮窗显示失败原因和下一步操作建议

#### 4.1.3 录音异常处理

- 麦克风被拒绝/未授权 → 不开始录音，引导用户前往权限页修复
- 录音时长过短（如误触） → 提示“未检测到有效语音”
- 录音设备不可用 → 提示检查录音设备
- 录音过程中异常中断 → 保留已记录的部分音频，并提示用户

#### 4.1.4 录音质量要求

- 应支持足够的采样率和位深度以保证识别准确率
- 不应在录音过程中引入明显的音频失真

---

### 4.2 语音转文字

#### 4.2.1 多引擎语音识别

应用应内置多套语音识别引擎，按优先级自动选择可用引擎：

- **本地 Whisper 引擎**（默认优先）：使用 OpenAI Whisper small 模型在本地完成语音识别，无需联网，保护隐私
- **macOS 系统语音识别**（备选）：利用 macOS 内置的 SFSpeechRecognizer，作为本地能力的补充
- **自定义本地引擎**（高级）：支持用户配置自定义的本地识别引擎路径

识别引擎不可用时，应给出明确提示，而不是静默失败。

#### 4.2.2 识别语言

支持以下语言选择：

- **自动识别**：由识别引擎自动判断语言
- **中文**
- **英文**

#### 4.2.3 识别模式

支持两种识别模式的取舍：

- **速度优先**：使用更轻量的模型或参数，加快识别速度
- **准确率优先**：使用更精细的模型或参数，提高识别准确率

#### 4.2.4 识别失败处理

- 识别结果为空 → 提示“未检测到有效语音内容”
- 引擎调用失败 → 保留错误信息，提示用户检查麦克风、权限或识别资源状态
- 所有引擎均不可用 → 明确告知用户，提示安装本地引擎或检查系统设置

#### 4.2.5 默认可用性

- 用户在首次安装后，不应需要手动配置任何识别资源即可使用基础语音识别能力
- 本地 Whisper 引擎应在首次启动时自动就绪

---

### 4.3 文本优化（大模型润色）

#### 4.3.1 优化规则

润色提示词默认要求大模型对识别文本执行以下优化：

- **纠错**：修正同音字、错别字
- **去重复**：删除口语中重复的词语和句子
- **去口头禅**：去除“嗯”、“啊”、“然后”等口语填充词
- **补全标点**：添加或修正标点符号
- **保持原意**：不改变用户原意
- **保留专有名词**：人名、地名、项目名、术语等不做修改
- **只输出结果**：不解释处理过程，直接输出最终文本

#### 4.3.2 提示词管理

- 支持多套提示词配置（提示词描述文件）
- 每套提示词包含两部分：**润色提示词**（用于语音输入）和**问答提示词**（用于语音问答）
- 提示词描述文件支持以下操作：
  - 创建新的提示词描述文件
  - 重命名提示词描述文件
  - 复制提示词描述文件
  - 删除提示词描述文件（需保留至少一个）
  - 恢复所有提示词为默认值
- 用户可自由编辑提示词内容
- 语音输入和语音问答有各自独立的提示词，不可互换

#### 4.3.3 模型未配置时的行为

- 未配置大模型时，语音输入直接输出转写文本，不进行润色
- 界面应明确说明：语音转写仍可用，但不会自动润色
- 语音问答在未配置模型时提示用户需要先配置模型

#### 4.3.4 模型调用失败时的行为

- 语音输入：保留可用的转写文本，输出转写文本（不润色），提示模型调用失败
- 语音问答：展示失败原因，提示用户检查模型配置或网络

#### 4.3.5 模型配置要求

- 支持配置以下参数：
  - 服务地址（Base URL）
  - 接口路径（API Path）
  - 模型名称
  - API 密钥
  - 调用温度（Temperature）
- 提供 OpenAI-compatible 接口兼容，用户可接入任何兼容服务
- 提供以下服务的预设模板，用户只需填写 API 密钥即可使用：
  - **DeepSeek V4**（api.deepseek.com）
  - **GLM-5.1 / 智谱 AI**（open.bigmodel.cn）
- 支持自定义服务配置
- 支持模型连接测试：一键测试当前配置是否能正常调用模型
- 模型配置修改后自动保存并立即生效

---

### 4.4 文本投递

#### 4.4.1 投递策略

文本投递采用**分级兜底**策略：

1. **写入系统剪贴板**（必须执行）：将最终文本写入系统剪贴板，确保内容不丢失
2. **尝试自动粘贴**（条件执行）：如果拥有输入控制权限，尝试模拟 Cmd+V 粘贴操作，将文本填入当前焦点输入位置
3. **返回投递结果**：告知用户投递状态

#### 4.4.2 投递结果反馈

投递完成后应明确告知用户：

- 文本是否已写入剪贴板
- 是否尝试了自动粘贴
- 自动粘贴是否成功
- 若失败，失败原因是什么

#### 4.4.3 自动粘贴失败兜底

- 自动粘贴失败时，文本仍在剪贴板中
- 用户可手动粘贴（Cmd+V）
- 提示用户检查输入控制权限设置

#### 4.4.4 文本回看

- 支持“粘贴前预览”（可选开关）：在自动粘贴前弹出文本回看窗口
- 回看窗口中用户可以：
  - 编辑/修改文本
  - 确认粘贴（Enter 键或点击确认按钮）
  - 放弃粘贴（Esc 键或点击放弃按钮）

---

### 4.5 语音问答

#### 4.5.1 问答与输入的区别

| 维度 | 语音输入 | 语音问答 |
|------|---------|---------|
| 快捷键 | 可配置（默认 Control+Shift+Space） | 可配置（默认 Control+Shift+.） |
| 用途 | 语音转文字后填入输入框 | 语音提问后查看答案 |
| 提示词 | 润色提示词 | 问答提示词 |
| 结果投递 | 自动粘贴/剪贴板 | 专用问答查看窗口 |
| 模型要求 | 可选（无模型则直接输出转写文本） | 必需（无模型无法使用） |

#### 4.5.2 问答结果展示

- 问答结果应通过通知提示用户
- 用户点击通知后，显示专用的问答查看窗口
- 窗口应包含：
  - 原始问题（以标签/徽章形式展示）
  - 模型的回答（完整内容）
  - 复制按钮（点击后将回答复制到剪贴板，并显示“已复制”反馈）
- 窗口尺寸应固定，内容较长时内部滚动，不能撑开窗口
- 窗口支持拖拽、调整大小
- 窗口应始终置顶（always-on-top），方便用户对照查看

#### 4.5.3 问答失败处理

- 未配置模型 → 提示用户需要配置模型才能使用问答功能
- 模型调用失败 → 展示失败原因（超时、网络错误、认证错误等）
- 转写失败 → 提示语音识别失败，不尝试调用模型

---

### 4.6 快捷键

#### 4.6.1 可配置的快捷键

应用提供以下可配置快捷键：

| 功能 | 默认快捷键 |
|------|-----------|
| 语音输入 | Control + Shift + Space |
| 语音问答 | Control + Shift + . |
| 加入词库 | Control + Shift + V |

#### 4.6.2 快捷键录入方式

- 采用**人性化的按键捕获方式**：用户点击“更改”按钮后，直接按下目标组合键进行录入
- 不需要用户手动输入键名文本（如“Control+Shift+Space”）
- 支持取消录入（如点击取消或按 Esc）
- 录入时显示当前按下的组合键

#### 4.6.3 快捷键冲突检测

- 应检测新设置的快捷键是否与已有功能冲突（如被其他应用占用）
- 发现冲突时应明确提示用户，建议更换其他组合键
- 录音快捷键和问答快捷键之间也应检测互斥

#### 4.6.4 快捷键生效机制

- 修改后自动保存并立即生效
- 注册失败时保留旧快捷键（不能因为新快捷键注册失败而导致没有快捷键可用）
- 主窗口关闭后快捷键仍应可用（后台常驻）
- 系统从休眠/锁屏恢复后快捷键应重新注册

#### 4.6.5 快捷键状态显示

- 设置页面应显示每个快捷键的注册状态（已注册 / 注册失败 / 冲突）
- 首页应展示当前配置的快捷键

---

### 4.7 系统托盘

#### 4.7.1 托盘图标

- 应用启动后应在系统托盘显示图标
- 图标应具有辨识度，使用 macOS 模板图像适配亮色/暗色主题
- 鼠标悬停时显示应用名称提示文字

#### 4.7.2 托盘菜单

托盘右键菜单至少包含：

- **显示窗口**：打开或恢复主设置窗口
- **退出**：完全退出应用（停止后台服务）

#### 4.7.3 托盘状态传达

- 托盘图标可根据应用状态（空闲 / 忙碌 / 错误）显示不同样式
- 异常状态时应让用户能够通过托盘获知

---

### 4.8 全局状态浮窗

#### 4.8.1 显示时机

在以下关键阶段显示桌面级状态浮窗：

- 正在录音
- 正在转写（语音 → 文字）
- 正在思考（大模型理解内容）
- 正在生成（大模型生成润色文本）
- 正在回复（大模型生成问答回答）
- 需要处理（权限、配置或执行错误）

#### 4.8.2 浮窗样式要求

- 位于用户当前使用显示器的底部居中位置
- 尺寸不宜过大，呈圆角胶囊/药丸形状
- 样式应简洁、美观、轻量
- 录音状态应有脉动/呼吸灯动画效果（如红色圆点闪烁）
- 不同状态使用不同的文字和图标区分

#### 4.8.3 浮窗行为要求

- 浮窗不能抢走用户当前输入焦点（不可聚焦）
- 浮窗应始终保持在其他窗口之上（置顶）
- 浮窗在任务栏中不可见（不显示为独立任务）
- 状态结束后浮窗自动消失（延迟适当时间）
- 浮窗消失后不应影响后续的文本回填操作

---

### 4.9 应用状态体系

应用应明确定义以下全局状态，所有窗口和组件同步显示：

| 状态 | 含义 | 触发条件 |
|------|------|---------|
| **空闲 (idle)** | 后台待命，等待用户操作 | 启动完成 / 操作完成 |
| **正在录音 (recording)** | 正在接收语音输入 | 用户按下语音输入/问答快捷键 |
| **正在转写 (transcribing)** | 正在将语音音频转换为文字 | 录音停止后自动进入 |
| **正在思考 (thinking)** | 大模型正在理解转写内容 | 转写完成后，调用大模型润色时 |
| **正在生成 (generating)** | 大模型正在生成润色结果 | 大模型开始输出润色文本 |
| **正在回复 (answering)** | 大模型正在生成问答回答 | 问答模式下，大模型开始输出答案 |
| **需要处理 (needs_attention)** | 出现权限、配置或执行错误 | 任何环节出现异常 |

状态变化的规则：

- 状态是全局唯一的，同一时间只有一个状态
- 状态变化时所有相关窗口（主窗口、状态浮窗等）应同步更新
- 状态从非空闲变为其他状态后，应能在合理时间内自动恢复为空闲（或进入“需要处理”）
- 错误状态（needs_attention）持续一段时间后应自动恢复为空闲

---

### 4.10 通知

#### 4.10.1 通知触发场景

- 语音输入完成（成功或失败）
- 语音问答结果就绪
- 权限缺失提醒
- 关键错误提示

#### 4.10.2 通知行为

- 通知不可用时，应在应用内部（主窗口或结果窗口）展示结果
- 问题/错误类通知应引导用户进行下一步操作（如打开设置、检查权限）

---

## 5. 设置与页面需求

### 5.1 整体页面框架

- 左侧边栏导航，右侧为内容区域
- 导航项使用图标+文字，清晰可辨识
- 当前页面高亮显示
- 页面内容区域应固定宽度，长文本内部滚动，不能撑开布局
- 常见设置直接可见，高级选项默认收起

### 5.2 首页

首页是用户打开应用后最先看到的页面，应展示应用的**就绪状态概览**：

- **状态指示**：当前应用状态（就绪 / 忙碌 / 异常），带状态徽章
- **状态描述**：用自然语言说明当前状态（如“就绪，等待语音输入”）
- **关键配置摘要**：
  - 语音输入快捷键
  - 语音问答快捷键
  - 当前使用的模型（或“未配置”）
  - 语音识别模式（速度优先/准确率优先）
  - 启用的词库词条数量
- **不应包含**：测试输入框、测试输出框、任何形式的测试功能

### 5.3 快捷键页

- 以列表形式展示所有可配置的快捷键条目
- 每个条目显示：
  - 功能名称
  - 当前设置的组合键
  - 注册状态（已注册 / 冲突 / 注册失败）
  - “更改”按钮（点击后进入按键捕获模式）
- 按键捕获模式下：
  - 按钮文字变为“按下组合键…”，等待用户按键
  - 实时显示当前按下的组合键
  - 提供取消按钮或按 Esc 取消
- 显示冲突提示（当新快捷键与其他已注册快捷键或系统快捷键冲突时）

### 5.4 模型页

- **服务选择**：分段控制器，选项包括“不使用”、“DeepSeek V4”、“GLM-5.1”、“自定义”
- **预设应用**：选择预设后自动填充服务地址、接口路径、模型名称，用户只需填写 API 密钥
- **配置项**：
  - 服务地址（Base URL）
  - 接口路径（API Path）
  - 模型名称
  - API 密钥（密码输入框，不展示明文）
  - 温度参数（滑块 + 数字输入，范围 0-2）
- **连接测试**：按钮触发模型连接测试，显示测试结果（成功/失败及原因）
- **未配置模型提示**：明确说明“未配置模型时，语音转写仍可用，但不会自动润色，也不能使用语音问答”

### 5.5 语音页

- **识别语言**：下拉选择或分段控件，选项包括“自动识别”、“中文”、“英文”
- **识别模式**：分段控件，选项包括“速度优先”、“准确率优先”（附带简要说明）
- **高级配置**：默认折叠状态
  - 自定义本地识别引擎路径（高级用户可指定外部引擎）
- **默认行为**：普通用户不需要手动填写任何识别资源路径

### 5.6 提示词页

- **提示词描述文件列表**（左侧或顶部）：
  - 显示所有提示词描述文件
  - 支持创建、复制、重命名、删除
  - 当前选中项高亮
- **提示词内容编辑区**：
  - 润色提示词编辑框：用于语音输入模式的文本润色
  - 问答提示词编辑框：用于语音问答模式的回答生成
  - 两个编辑框应有足够的可视高度，支持多行编辑
- **恢复默认**：提供“恢复默认提示词”按钮，将选中描述文件的提示词重置为默认值
- **默认提示词内容**：
  - 润色提示词应明确要求：纠错、去重复、去口头禅、补全标点、保持原意、保留专有名词、只输出最终结果
  - 问答提示词应明确要求：简洁、有条理的回答，不解释无关内容

### 5.7 词库页

- **添加词条**：
  - 输入框：填写词条名称
  - 输入框：填写别名（可选，逗号分隔）
  - 添加按钮
- **自动学习开关**：控制是否自动从用户确认的文本中学习新词
- **词条列表**：
  - 每个词条显示：名称、别名、启用/停用开关、删除按钮
  - 支持启用和停用（停用的词条不参与识别纠错和大模型润色）
- **词库用途说明**：
  - 服务于语音识别纠错（优先匹配词库中的词汇）
  - 服务于大模型润色（作为上下文提供给模型）

#### 5.7.1 词库分类（设计理念）

词库分为三类，但用户无需理解这些概念：

- **固定词库**：用户主动添加的人名、项目名、产品名、术语等，优先级最高
- **自动词库**：应用根据用户长期确认或修正后的内容，自动沉淀高频词和纠错对
- **临时上下文词库**：根据用户近期输入内容、当前上下文和最近使用内容提取临时候选词

#### 5.7.2 无感维护原则

- 用户不需要频繁打开词库页面进行手动维护
- 应用应在后台观察“识别结果”和“最终确认文本”的差异，自动生成候选纠错对
- 候选词不应立刻强制加入，应在低打扰位置展示，让用户一键确认或忽略
- 高频、多次出现、置信度高的候选词可自动提高权重
- 每次调用大模型时，只传入与当前内容最相关的一小部分词条，避免提示词过长

### 5.8 日志页

- **日志过滤**：
  - 按级别过滤：全部 / 错误 / 警告 / 信息 / 调试
  - 按关键词搜索
- **日志列表**：
  - 每条日志显示：时间戳、级别、消息内容
  - 支持滚动查看历史记录
  - 保留最近一定数量的日志条目
- **操作按钮**：
  - 刷新：重新加载最新日志
  - 清除：清空所有日志
- **日志文件路径**：显示日志文件的存储位置

### 5.9 权限页

#### 5.9.1 权限检查项

| 权限 | 用途 | 检测方法 |
|------|------|---------|
| 麦克风 | 录音 | 系统权限状态检测 |
| 辅助功能（输入控制） | 自动粘贴到目标输入位置 | 系统权限状态检测 |
| 通知 | 结果通知和错误提醒 | 通知能力检测 |
| 后台运行 | 托盘常驻和快捷键保持 | 状态检测 |

#### 5.9.2 每项权限的展示

- 权限名称
- 权限用途说明
- 当前状态（已授权 / 未授权 / 未知）
- 操作按钮：
  - 未授权时的“请求授权”按钮
  - “打开系统设置”按钮（跳转到系统偏好设置的对应权限页）
  - “重新检测”按钮

#### 5.9.3 权限引导策略

- 应用启动时应主动检查所有必要权限
- 权限不足时应自动引导用户进入权限页
- 不要等到用户实际触发录音/粘贴操作失败后才提示权限问题
- 用户授权后不应要求反复重启应用，除非确实必要
- 权限检测异常时应给出可理解的说明（如系统版本不兼容等）

## 6. 权限与失败兜底

### 6.1 权限不足的兜底策略

| 权限缺失 | 影响 | 兜底方案 |
|----------|------|---------|
| 麦克风不可用 | 无法录音 | 引导用户授权；不开始录音 |
| 辅助功能未授权 | 无法自动粘贴 | 文本写入剪贴板，提示用户手动粘贴 |
| 通知不可用 | 无法发送系统通知 | 在应用内展示结果 |
| 后台运行受限 | 快捷键可能失效 | 提示用户检查系统设置 |

### 6.2 功能失败的兜底策略

| 失败环节 | 影响 | 兜底方案 |
|----------|------|---------|
| 语音识别失败 | 无法获取文字 | 显示失败原因；不误认为已成功 |
| 大模型未配置 | 无法润色/问答 | 直接输出转写文本；问答提示需配置模型 |
| 大模型调用失败 | 润色/问答失败 | 保留转写文本直接输出；提示调用失败 |
| 自动粘贴失败 | 文本未能填入 | 文本在剪贴板中；提示用户手动粘贴 |

## 7. 界面与体验要求

### 7.1 整体设计风格

- 清爽、简洁、美观，符合 macOS 设计语言
- 设置界面安静、克制，不做营销式首页
- 常用操作清晰可见，复杂选项默认收起
- 页面内容不能因为长文本被撑开，文本区域必须固定尺寸，内部滚动
- 滚动条样式应与整体设计一致，风格统一
- 按钮、状态标签、权限提示应有明确的层级和视觉区分
- 使用一致的图标系统

### 7.2 后台体验

- 应用应尽可能退到后台运行
- 用户主要通过快捷键触发功能，不应频繁打开主设置窗口
- 关键状态通过托盘图标、状态浮窗、通知或简短提示传达
- 不应抢夺用户输入焦点
- 不应打断用户正在进行的输入上下文
- 主窗口关闭（点 X）应隐藏而非退出

### 7.3 反馈及时性

- 状态变化应即时反映在所有可见界面上
- 加载、调用等耗时操作应有加载状态指示
- 避免用户误以为应用卡死或无响应

---

## 8. 非功能需求

### 8.1 可靠性

- 主窗口关闭不应导致后台能力失效
- 快捷键、录音、转写、模型调用、文本投递应形成稳定的闭环
- 每一步失败都必须有兜底方案或明确的错误提示
- 应用应能处理系统休眠/唤醒、锁屏/解锁等场景，恢复快捷键注册

### 8.2 易用性

- 默认配置应尽量“开箱即用”，安装后即可使用基础功能
- 普通用户不需要理解识别资源、引擎路径、模型文件等技术细节
- 权限引导必须具体、可操作、可重新检测
- 设置项应提供合理的默认值
- 错误提示应使用用户可理解的自然语言，而非技术错误码

### 8.3 隐私保护

- 语音识别默认应尽量在本地完成（使用 Whisper 本地引擎），不上传音频到第三方服务器
- 用户的 API 密钥、词库、提示词等配置应保存在用户本地，不泄露
- 是否保存历史语音数据应由用户控制
- 日志文件不应记录敏感信息（如完整的 API 密钥）

### 8.4 性能要求

- 语音转写应尽可能快，减少用户等待时间
- 提供速度与准确率的选择，让用户根据场景取舍
- 状态反馈要及时（录音开始、转写进度等）
- 应用启动应迅速，资源占用合理
- 后台运行时不应占用过多 CPU 或内存

### 8.5 兼容性

- 支持 macOS 操作系统
- 适配亮色/暗色系统主题
- 适配多显示器场景（状态浮窗出现在用户当前使用的显示器上）

## 9. 验收标准

### 9.1 基础功能验收

- [ ] 用户能配置大模型并测试连接
- [ ] 用户能按快捷键录音，松开后自动完成转写
- [ ] 已配置大模型时，转写文本会被润色后输出
- [ ] 未配置大模型时，转写文本仍可直接输出（不润色）
- [ ] 结果优先尝试自动填入目标输入位置
- [ ] 自动填入失败时，文本写入剪贴板作为兜底
- [ ] 语音输入和语音问答使用各自独立的快捷键，互不混淆
- [ ] 主窗口关闭后，快捷键仍然可用
- [ ] 托盘菜单的“显示窗口”能可靠唤起主窗口
- [ ] 托盘菜单的“退出”能完全退出应用

### 9.2 权限与引导验收

- [ ] 应用启动时主动检查必要权限
- [ ] 权限缺失时自动引导用户进入权限页（而非等到操作失败后才报错）
- [ ] 每项权限都有明确的用途说明、当前状态和操作入口
- [ ] 麦克风权限可通过应用内请求按钮触发系统授权弹窗
- [ ] 辅助功能权限可引导用户跳转系统设置页

### 9.3 界面验收

- [ ] 所有设置页面布局正常，长文本不会撑坏页面布局
- [ ] 文本编辑区域固定尺寸，内部滚动
- [ ] 首页不包含测试输入框或测试输出框
- [ ] 状态浮窗在关键阶段正确显示和隐藏
- [ ] 状态浮窗不抢夺用户输入焦点
- [ ] 问答结果窗口内容较长时可正常滚动

### 9.4 交互体验验收

- [ ] 快捷键修改采用按键捕获方式（直接按键录入），而非手动输入文本
- [ ] 快捷键冲突能被检测并提示
- [ ] 快捷键修改后自动保存并立即生效
- [ ] 提示词支持多描述文件管理（创建、复制、重命名、删除）
- [ ] 提示词可恢复为默认值
- [ ] 词库支持添加、编辑、启用/停用、删除词条
- [ ] 模型连接测试功能可用
- [ ] 日志可查看、过滤搜索、清除

### 9.5 稳定性验收

- [ ] 系统休眠/唤醒后快捷键恢复正常
- [ ] 系统锁屏/解锁后快捷键恢复正常
- [ ] 录音过程中关闭主窗口不影响录音任务
- [ ] 长时间后台运行无内存泄漏或性能退化
- [ ] 所有功能失败都有兜底方案，不会静默失败
